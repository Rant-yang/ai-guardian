# 统一发现与接入能力（2026-11-04）

产品目标是一次扫描、用户选择、预览变更、确认接入、真实动作验证，后续窗口自动加载接入。统一体验不意味着任何客户端都支持同一种拦截协议。

`guardian/client_catalog.py` 现在统一维护发现签名和是否存在安装适配器。扫描与前端选择、后端安装白名单共享目录；新增目录项不会自动获得配置写入权限。现有安装器仍需逐个实现，不能仅将 `installable` 改为 true。

## 框架重构落实

### 配置根目录一致性

客户端目录声明现在包含默认配置根和覆盖环境变量。扫描、配置范围 ID、预览、安装、状态与撤销共同调用路径解析器：Claude 使用 `CLAUDE_CONFIG_DIR`，Codex 使用 `CODEX_HOME`，OpenCode 使用 `XDG_CONFIG_HOME`。安装处理器接收已解析的目标，避免自行重算后写到不同位置。空覆盖值采用默认目录；相对路径拒绝写入并在扫描中禁用接入，不静默回落。守卫不改这些环境变量。

测试覆盖重定向目录完整安装/撤销、默认目录未创建、用户字段与 Codex 模型配置保留、预览后覆盖目录变化使计划失效。32 项专项、9 项原安装、75 项前端和 41 项后端集成通过，共 157 项。

范围仍是守卫进程当前继承的环境，不能自动知道其他终端临时设置、WSL 环境或用户配置正文中的覆盖值。此轮没有读取认证信息，也不声称所有配置实例都已发现。

依据：[Claude 环境变量](https://code.claude.com/docs/en/env-vars)、[Codex 配置和状态位置](https://developers.openai.com/codex/config-advanced/)。与前述 Pipelock 的显式配置根、CC Switch 的按客户端原生路径同步思路一致。

### 服务端点恢复（2026-11-04 后续）

服务层新增 `ServiceLease` 数据目录进程锁。锁在凭据创建、数据库打开和审批撤销之前获取，覆盖整个后台生命周期；同一数据目录不能由不同端口的两个进程同时使用。锁由操作系统持有，崩溃或退出后释放，锁文件保留以避免删除/重建导致锁对象分裂。不同数据目录仍可独立启动，便于隔离验收。此约束不依赖桌面启动脚本。

4 项进程生命周期测试通过：同目录互斥/不同目录独立、异常退出释放、重复启动不触碰原数据库或凭据、真实后台在重复启动被拒后继续健康响应且端点不变。测试只操作独立临时目录，未终止用户 Agent。

借鉴 Orca 本地端点文件设计，守卫在成功绑定端口后原子发布数据目录内的 `service-endpoint.json`。文件只包含版本、固定回环主机与端口，不包含凭据，也不能指定远程 URL。Claude / Gemini / Codex 命令钩子及 OpenCode 插件按请求刷新；显式 `--port` 或 `GUARDIAN_PORT` 优先，文件不存在时兼容旧版 8765，文件损坏或超大时按观察/保护故障策略处理，不静默降级到旧地址。

OpenCode 适配器版本更新为 `endpoint-3`。已运行旧插件需正常重启客户端才加载代码；同一个新版实例可在后台端口描述更新后继续发送检查、回执和心跳，无需再次写用户配置。命令钩子每次启动读取当前脚本，不需修改已安装命令。端点更新不恢复或重放动作，也不证明安装范围与运行实例已完成握手。

验证：2 项 Python 端点读写、4 项连接、6 项真实命令钩子 HTTP 测试、5 项 OpenCode 测试及 41 项后端接口测试通过。包含不传端口运行三种命令钩子、同一个 OpenCode 插件实例切换端点、畸形与远程端点拒绝、保护故障策略。尚未以真实用户 OpenCode 窗口验证后台换端口；这不等于所有安装生命周期已完整。

### 能力、身份与状态分层

### 安装加载关联首个适配（后续更新）

新增 `installation_binding.py`，由后台固定的配置路径核对加载声明；请求不能提供文件路径。OpenCode 用户级入口携带配置范围 ID 和 loader_revision，新插件 `scope-4` 随心跳上报。结果明确区分未上报、其他配置、配置已变更、已撤销、不可读取和匹配本地配置。这不是进程证明或远程认证，不能作为动作授权，也不证明拦截生效。共享上报令牌的其他本地进程仍可能声明相同信息。

旧版精确匹配的入口作为可补齐配置处理，用户通过原有预览流程升级时先备份；任意自定义改动仍不覆盖。此轮没有修改本机用户入口，所以已有全局接入仍需在用户方便时升级并重新加载才能报告关联。无声明的旧插件保持兼容，不能误报匹配。其他命令钩子暂无此声明能力。

连接保留期内禁止同一运行 UUID 改绑配置范围；每次心跳重新核对文件，后台重启需新心跳重建。诊断分别统计在线且匹配、在线但未匹配的实例。35 项 Python 专项、80 项前端/插件及 41 项后端集成通过，覆盖变更、撤销、重启、新旧入口升级、备份、拒绝覆盖自定义内容与声明转发。

`adapter_contracts.py` 统一声明已实现协议的执行前检查、阻断、回执、心跳、审批恢复方式、导航方式及当前适配器版本。扫描、接入计划、连接注册和诊断共享声明；心跳自报字段不能提升能力。Codex 原生 Hooks 与合成 MCP 演示独立描述。能力仅表示代码支持，不能当作某用户安装已通过验收。

`installation_identity.py` 为“客户端 + 本机运行环境 + 配置路径”生成稳定配置范围 ID，为每个可执行候选另生成不同类型的 ID。扫描与预览的配置范围 ID 一致；路径、客户端或运行环境变化会产生不同 ID。ID 不是凭据。当前只发现本机用户范围，不冒充已经支持 WSL 或任意配置目录；也不凭可执行文件猜测其实际使用哪份配置。

运行实例继续使用适配器实例 UUID，会话与动作继续保留各自原生关联。相同实例 UUID 在保留期间不能被重新绑定到另一项目或适配器。配置范围与运行实例之间当前明确标记未验证，后续需要适配器加载握手才能建立可信关联；不能只因路径存在就补造绑定。

诊断新增独立生命周期字段：configuration、presence、observation、protection、navigation。在线与模式设置不能自动提升为保护已验证；原生确认与需重新发起分别显示。已有回执缺口、历史事件、旧插件版本诊断继续保留。

## 2026-11-04：Qoder 实验协议接入（后续更新）

此前表格中 Qoder「仅发现」状态由本节更新：当前可通过统一扫描向导预览安装到 `~/.qoder/settings.json`。三类 Hook 为 PreToolUse / PostToolUse / PostToolUseFailure，使用共享 JSON 安装器、备份/撤销、模式配置与执行回执存储。安装仍需用户选择和预览确认，不因发现候选就写配置。

依据 [Qoder 官方 Hooks](https://docs.qoder.com/cli/hooks) 和 [协议参考](https://docs.qoder.com/cli/hooks-reference) 独立实现。Windows 明确指定 PowerShell，其他平台指定 Bash；5 秒 Hook 超时，内部 HTTP 超时 3 秒。命令参数按对应 Shell 引号处理。没有更改模型、API 或其他插件设置。

动作判定：pass 返回空对象，保留客户端原有权限；deny 返回原生拒绝；review 返回 ask 交原生权限确认，不创建控制台重试授权。执行回执按 qoder-hook + 会话 + 调用 ID 关联，返回正文仅在 Hook 端扫描，后端不保存正文。模式和来源筛选已加入 Qoder，原生确认提示使用实际客户端名称。

验证：能力契约 6、发现 10、接入计划 12、安装集成 11、Hook 故障 6、后端集成 42、前端 76，共 163 项通过。包含隔离目录安装/卸载、带单引号及美元符号路径的 PowerShell 启动、观察/保护判定、原生 ask、成功/失败回执、服务异常和不保存输出正文。后端测试实际运行 Python Hook 子进程与隔离 HTTP 服务；这不等于 Qoder 真实会话验收。

## 2026-11-11：Qoder Windows 外层 Shell 兼容修复

用户实测发现设置了 shell=powershell 的 Orca Hook 仍被 Bash 解释，出现语法错误。此前直接 PowerShell 单路径测试不足以证明真实客户端启动链兼容。新 Guardian 安装器显式调用 powershell.exe，并用 UTF-16LE 编码参数传递固定脚本，避免 Bash 对 PowerShell 语法和路径字符展开；保留原观察/保护逻辑。已在 PowerShell 与 Git Bash 下验证特殊路径、缺少脚本的观察降级和标准输入原样传递。未据此宣称真实 Qoder 会话全部动作已通过。

旧版本本项目入口可由接入预览就地升级，保留第三方 Hook。预览对第三方裸 PowerShell 片段给出兼容性提示，不自动执行或修改它们；本次本机 Orca 修复是在用户报告并要求处理后的精确匹配维护，非安装器的默认行为。备份了用户 settings.json，仅修改 11 个 Orca 与 3 个 Guardian command 启动包装，Orca 脚本正文、其他字段和用户设置保持。Orca 后续更新可能重新生成原入口，需重新检查。

验证按钮改为“检查接入是否生效”；它开始等待无害动作检查，不证明用户已经重启，不自动向 Agent 发送任务。相关回归：14 项安装器、12 项接入流程、87 项前端通过。官方协议依据：https://docs.qoder.com/cli/hooks 。当前官方文档支持 shell 和无 Shell 的 args 执行方式，但未知旧版能力不直接假定适用。
