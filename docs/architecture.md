# 当前架构与待完成边界（2026-11-05）

产品采用本机常驻服务，客户端通过各自支持的 Hook 或扩展检查工具动作，控制台和透明悬浮窗读取同一事件源。客户端目录中出现某个产品，不等于已经实现或验证它的监督能力。

## 接入与配置

`client_catalog.py` 描述客户端和配置位置，`discovery.py` 与 `discovery_paths.py` 进行有限发现。`adapter_registry.py` 只调度代码中登记的安装处理器，不根据外部目录执行任意插件代码。新增客户端必须分别提供发现描述、经过审查的接入处理器、能力契约和真实执行验证。

`onboarding.py` 管理扫描、预览和限时应用计划；预览绑定目标位置与文件状态。配置修改通过专用安装器和 `config_files.py` 保留已有设置，`hook_configuration.py` 检查匹配范围、超时和处理器等静态语义。静态检查通过不等于客户端已信任或加载扩展。安装、撤销和升级须保留用户其他配置。

`adapter_contracts.py` 集中声明执行前检查、阻断、回执、心跳、审批恢复和导航能力；前端展示目录由该契约生成。Claude、Codex、OpenCode、Gemini、Qoder、Pi 的实现与验收范围不同，不能用其中一个客户端的测试结果提升其他客户端的状态。

## 动作与审批

客户端适配器 → 认证回环 HTTP → 策略/规则与可选语义检查 → SQLite 决策事件 → 客户端落实决定 → 独立执行回执。

`engine.py` 用客户端、会话、调用身份绑定不可变参数与工作目录摘要。规则命中、授权和执行结果是不同事实。缺少回执保持未知；规则未命中不代表已证明安全。事件保存脱敏动作摘要与原因，不保存完整原始参数。

审批分两条路径：支持原生确认的客户端在原客户端判断；需重试的客户端通过控制台取得绑定动作、有有效期的单次授权，随后由用户重新发起。Pi 已上报独立原生确认审计；其他客户端未提供这一回执时不推测用户决定。策略变化、服务重启和过期使相应待处理授权失效，不自动重放工具。

## 运行与观测

`service_lease.py` 与启动锁避免同一安装重复启动，`service_endpoint.py` 发布本机端点；共享端点解析支持后台换端口后的重新读取。管理令牌和适配器令牌分离，桌面打开页面使用单次连接票据。

正常停止使用管理权限的 `/api/service/shutdown`，核对当前进程 ID 并显式确认。先拒绝新连接，再停止监听、等待已接受 HTTP 请求退出，随后取消并等待本地语义准备/复核工作，关闭定位存储，最后关闭事件数据库。`stop-background.ps1` 仍核对固定进程句柄、创建时间、可执行路径和项目身份；默认等待正常退出 20 秒，未完成时报错而不强杀。`-Force` 为显式应急选项，旧后台不支持协议时也不静默强杀。排空等待不冒充请求取消，运行中的长任务可能让关闭超过 20 秒；本机取消不证明远端模型已停止计算。

`health.py` 提供低成本服务健康投影。`/api/health` 的 ready 只表示 HTTP 正在响应、规则已加载且最近存储状态正常，不代表所有客户端已接入或本地模型可用；它不扫描客户端、不启动推理、不引用历史验收标签。存储写入异常报告 degraded，错误恢复后可恢复 ready。schema 版本独立于 API 版本。

`http_capacity.py` 在创建线程和读取请求头之前限制并发连接，默认最多 32 个活动连接。超过容量返回无决定的 503、Retry-After: 1 并关闭连接，不排入应用层无限队列；TCP 监听 backlog 为 32，实际由操作系统管理。请求头、正文和写响应使用 5 秒 socket 空闲超时，线程启动失败或处理结束都会归还容量。健康接口返回活动数、上限和累计拒绝数；饱和时健康接口本身也可能被拒绝。

读取请求头与正文另有合计 10 秒的绝对时限，每个活动连接使用一个可取消计时器；持续发送少量字节不能延长它。到期中断输入，条件允许时返回 408，否则关闭连接，不进行动作评估。完整输入读取后取消计时器，不用关闭 socket 冒充取消已经开始的模型或数据库工作。正文实际长度必须等于声明长度；重复 Content-Length 和 Transfer-Encoding 均拒绝。Windows 预期断连正常结束，不打印内部异常堆栈。锁等待和推理处理的总耗时不是这一输入时限的覆盖范围。

`overview.py` 汇聚配置、心跳、当前启动后的检查和回执，逐客户端给出诊断。历史成功不会掩盖其他会话的回执缺口；过期或撤销的原生审批不再计为等待用户决定。配置、在线、收到动作和实际保护分别呈现。`navigation.py`、`origin.py` 和来源定位存储负责返回会话；请求打开成功不是窗口已定位的证明。

`web/app.js` 与桌面外壳提供同一数据源的完整控制台和悬浮处置入口。现有球体、光轨、拖尾、粒子抽取与脉冲保留；视觉效果不承担保护状态的唯一表达。

## 模型与验证

默认本地规则，可选本地语义检查和事后模型复核。`semantic_gate.py` 与 `reviewer.py` 共用有界模型执行槽，显式处理超时和失效。云端业务 Agent 的动作仍可通过本地适配器监督；这不等于已完成云端安全复核产品能力。不得静默把本地失败变成云端数据发送。

验证分为纯逻辑、实际本机 HTTP、真实客户端配合本机合成模型、人工界面体验。`scripts/verify_*` 的合成规则和固定模型验证执行边界，不能作为生产规则准确率。Pi 1.5.0 的 CLI/RPC 十场景已验证（含持久会话恢复身份核对）；终端 UI、运行中重载等边界见 [Pi 接入说明](pi-integration.md)。打包采用显式白名单与本地 Python 静态依赖检查，不打入私有配置、模型或 node_modules。

## 仍需完成

1. 原会话精准返回的跨终端、标签页与桌面客户端验收；不得把降级打开应用显示成定位成功。
2. 更多客户端的明确版本真实执行、升级、运行中重载及卸载验证；发现能力不能代替适配能力。
3. 全新 Windows、不同安装路径和依赖缺失条件下的完整安装体验，以及跨机器卸载恢复。
4. HTTP 已有连接上限、503 背压、空闲超时、绝对输入时限和正常排空关闭；仍需补全处理阶段时间预算、长任务停止体验及长期高负载验证。基础仍为 ThreadingHTTPServer，未替换成外部 Web 服务框架。
5. 规则和语义检测独立评估、误报漏报反馈，以及云端复核的数据范围和显式配置。
