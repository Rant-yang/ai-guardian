# 真实模式、规则与审批（2026-10-31）

## 操作入口

双击桌面 Guardian，左侧“真实客户端模式”分别选择 Claude Code、Gemini CLI、OpenCode、Codex 原生 Hooks 的观察或保护，并点击保存。设置存放于 `.local/runtime-modes.json`；后台下一次检查使用新设置，已执行或正在执行的动作不追溯取消。每张卡片显示最近一次真实检查的实际模式和时间，不能把保存成功等同于插件已经加载。

本轮升级后 OpenCode 需要重启一次以加载新版插件。Claude 已添加执行后钩子，重启一次加载回执配置。之后模式切换不需要重启。右侧“演示观察／演示保护”仅作用于合成演示，真实设置不再与其混用。默认仍为观察，不替用户切换为保护。

## 判定与用户选择

观察：命中风险只告警，保留原始建议；不覆盖客户端自己的权限决定。

保护：确定性拒绝优先于复核，复核优先于告警。通过表示 Guardian 不阻止，客户端原有权限检查仍然有效。

- **拒绝**：阻止这次工具调用；不能通过单次审批按钮覆盖拒绝规则。可在客户端修改操作方案后重新检查。
- **Claude 复核**：返回原生 `ask`。用户在 Claude 的权限提示中决定；Guardian 不另发一份授权，也不把未收到的确认结果标为已授权。
- **OpenCode/Gemini/Codex 原生 Hooks 复核**：当前调用停止，控制台提供“允许一次重试／拒绝本次”。允许后用户在原会话明确重试同一动作，不自动重放、不假装恢复挂起工具。Gemini 通过返回拒绝协议停止；未接入执行后回执。

单次授权绑定客户端、原会话、工具、完整参数摘要及规则版本。有效期从事件创建起 5 分钟；新调用必须参数完全一致且使用新的调用 ID。重复上报同一个调用 ID 不会使被拒绝的原调用变成可执行。参数或会话变化须重新检查；并发重试仅能消费一次。切换/保存模式会撤销尚未使用的授权。规则升级后旧授权不会匹配。

审批页显示工具、有限的文件名/目标主机、命中理由和可能影响，不保存完整命令、请求体或 URL 凭据。完整参数需在原客户端核对；授权仍绑定完整参数摘要。

## 回执含义

| 展示 | 证据 |
|---|---|
| 拒绝决定 / 尚无执行回执 | 已返回决定，尚无执行方确认 |
| 适配器报告本次调用已停止 | OpenCode 执行前插件发送停止回执 |
| 工具已返回 | OpenCode `tool.execute.after`；不代表业务目标成功 |
| 客户端报告执行成功 / 失败 | Claude `PostToolUse` / `PostToolUseFailure` |
| 已授权、待重试 | 用户批准下一次匹配的调用；尚未执行 |

回执属于客户端报告，不是独立操作系统审计。Claude 原生拒绝和 Gemini 暂无通用停止回执时保留未知，不虚构阻断成功。

## 规则包

`guardian/rules.json` 独立管理规则，`guardian/rules.py` 负责匹配与最小化动作摘要。版本为 `0.2` 加内容摘要及工具规范化版本；修改规则后重启后台加载。当前 8 个匹配项（7 类风险，含合成上传专用项）：

1. 疑似指令注入：告警。
2. 递归删除、磁盘格式化等破坏性命令：拒绝；补充反序短参数、PowerShell/cmd 表达。
3. 网络提交/上传：复核；另有合成上传匹配项。
4. 下载内容直接交给解释器：复核。
5. 编码命令执行：复核。
6. 凭据文件访问：复核，包括 `.env`、私钥、部分认证配置路径。
7. 系统防护设置变更：复核。

这仍是正则启发式，不是完整 Shell 语法分析；引用可能误报，别名、拼接与间接脚本可能漏报。仅检查接入点传来的参数，未检查所有文件内容、工具返回文本或模型内部状态。尚未接入模型语义复核。

## 接入健康与规则覆盖（2026-11-02）

控制台分别展示配置状态、本次服务启动后收到的检查与回执、最近检查时间以及设置模式/最近实际模式。统计只覆盖最近 200 条事件；历史记录不证明当前在线，执行回执也不证明所有工具均已受到保护。Codex 原生信任状态无法从配置文件直接证明，仍由客户端确认。

OpenCode 有心跳，超时显示待核对；其他 Hooks 为按动作触发，没有动作时不应判定离线。桌面悬停工具栏提供简短状态，服务断连时继续显式提示。缺失部分 Claude/Codex 钩子可在接入向导中预览补齐；扫描不自动修复。

常见工具别名会进入同类规则检查；原始工具名与完整参数仍用于审批绑定。未知工具或无法解析的命令结构标注“专用规则未覆盖”，仅保留通用文本信号检查。已支持工具的未命中显示“未命中规则”，不承诺安全。


首次升级到令牌拆分版本后，重新双击 Guardian 启动器以获取新的单次管理连接；旧页面内存中的上报令牌不再具有管理权限。手动连接使用 `.local/admin-token`，不要向 Agent 提供此管理令牌。已安装钩子的文件路径和原上报令牌均不变。

## 2026-11-03：异常决定与故障策略加固

发现并修复适配器响应校验缺口：OpenCode 原先在验证 verdict 前覆盖 mode；缺失或无效模式可使故障分支失去本地保护语义。现在 Claude/Gemini/Codex/OpenCode 都先完整校验 mode、verdict、findings，再接受响应。findings 只允许有界规则标识，不回显异常响应中的任意文本。Python 钩子限制决定响应为 64 KiB。

合法服务器响应仍可按用户控制台设置切换模式；异常响应保留本地故障策略：保护模式返回拒绝/抛出工具前停止，观察模式只提示检查不完整。损坏输入仍先读取本地模式；执行后钩子遇到损坏模式配置只提示回执不完整，不输出虚假的执行前拒绝。

这些是已加载适配器的协议验证，不是操作系统强隔离。加载失败、客户端禁用 Hooks、脚本或解释器丢失仍是覆盖缺口；OpenCode 已启动实例需要重启以载入本轮模块更新。未自动重启用户 Agent 或修改全局配置。

规则现已更新至 0.3，规范化契约 tools2：凭据访问只使用目标路径，补充 npm/PyPI 凭据及相对路径识别；删除规则补齐拆分短参数。当前能力与明确失败样本见 [规则评测](rule-evaluation.md)。本地模型按需摘要复核已另行提供，但仍不参与执行前规则判定。

## 存储提交失败（2026-11-03）

事件、单次授权消费、审批、执行回执、反馈、复核和历史清理统一由事务提交。任一步或提交失败都会回滚；检查接口返回 503 无有效决定，已加载适配器继续按本地观察/保护故障策略处理。失败的审批不会留下可用授权；失败的授权消费会恢复原来尚未用掉的单次授权，后续成功匹配仍只能使用一次。

如果回滚本身失败，该连接被标记需重启，拒绝继续读取可能未提交的状态或进行写入。存储健康返回 write_failed/restart_required，控制台与悬浮状态标签显示异常。成功的后续事务可解除 write_failed；需重启状态不会自动解除。不回显异常中的路径或数据库细节。

模式保存先撤销旧授权，再写模式文件，避免撤销失败却已经切换模式；若随后模式文件保存失败，模式保持原值，但旧授权可能已被保守撤销。无效客户端/模式在撤销前拒绝。

验证包括提交失败注入、回滚失败注入，以及临时磁盘 SQLite 上真实读锁导致的提交失败与恢复。未模拟真实磁盘耗尽、断电或硬件损坏，不能把这些测试写成其验收通过。事务边界调整后 latency_ms 只描述持久化前引擎工作，不包含外层锁排队或 HTTP 往返。


## 回执诊断：按动作核对

控制台按本次服务启动后的每条动作核对回执。一条旧动作成功返回，不再掩盖同客户端其他会话的未知结果。非待审批动作超过 30 秒仍无回执，显示“部分动作回执待核对”，列出涉及会话数量，并提供最多十条对应事件的查看按钮。该按钮只筛选 Guardian 事件，不执行、重试或批准客户端动作。

30 秒仅是诊断提示阈值，不是工具执行超时：长任务可能仍正常执行，所以不标记失败，也不据此断言保护失效。待审批且尚无回执的动作另计；历史、演示记录不算本次缺口。晚到回执会自动消除相应缺口。范围仍是最近 200 条事件，不能视作完整审计。

## 悬浮提示同步处置状态

悬浮提示随服务刷新显示已授权待重试、授权已使用、已撤销、已过期和用户拒绝，不再在处置后始终显示等待复核。审批状态与执行回执分别描述：原调用被停止的事实仍保留；已使用授权提示查看另一次重试的回执，不能据此显示执行成功。工具返回、客户端报告成功、客户端报告失败也分别显示。

## 待审批详情与提交时状态

待审批详情只有在 execution_state=blocked 时才显示适配器已报告停止。缺少该回执时，显示已返回要求停止并复核的决定，但尚未确认原调用停止；用户仍需核对客户端。尤其 Codex 拒绝后可能没有执行后回执，不能将协议决定当作已独立确认拦截。

审批按钮点击时再次检查当前选中事件、连接、隐私与回放状态，并忽略同一按钮提交期间的重复点击。事件切换或开启隐私后旧按钮不再发送请求。此检查是前端交互边界，服务端仍以精确参数绑定、有效期、待审批状态和事务保证授权一致性；不撤回已发出的合法请求，也不替代服务端鉴权。

55 项前端回归通过，新增测试覆盖无回执/停止回执文案以及选中事件变化、隐私、回放、离线时不提交。无需重启后台；完整控制台重新加载前端后生效。未对用户真实动作审批或重试。

## Shell 凭据读取的目标摘要

之前 Shell 敏感文件规则能命中路径，但动作摘要主要提取结构化文件工具目标，审批详情可能没有对应文件名。现在对已有字面量读取解析器识别且命中凭据路径模式的目标，额外展示最多 80 字符的文件名，整体仍最多 6 个去重目标。不展示父目录或命令正文，不把 head 的数量选项、普通命令参数或 echo 中引用的示例当成凭据文件目标。

6 项 Shell 目标测试与 6 项工具覆盖测试通过；存储测试确认具体私有目录不进入历史，原始完整参数摘要绑定保持一致。只增加摘要信息，不改变检测结果、规则版本或授权范围。对于无法解析的命令仍提示在客户端核对完整参数；文件名本身也可能含敏感信息，录屏隐私模式仍会隐藏详细目标。后台实现待下次重载后对新事件生效，旧历史不重算。

## 上报工作目录的授权绑定（tools8）

单次授权和同调用 ID 去重新增 cwd-v1 摘要：同会话、同工具参数但客户端上报目录不同，不能复用原授权；目录从已上报变为缺失也不匹配。目录字符串只用于摘要，不写入历史或展示原路径，不做文件探测、路径规范化或链接解析。tool_input 内已有 workdir 等字段仍由原参数摘要绑定。

Codex 规范化保留原生 cwd；Claude/Gemini 原始 payload 若提供 cwd 可直接使用；OpenCode 插件新增发送插件实例的 directory，实际工具参数中的工作目录仍以完整参数绑定。客户端未提供 cwd 时保留 unreported 并在审批详情提示，不能保证其未上报的执行环境没有变化；插件目录也不证明进程运行时 cwd。此方案不锁定文件内容、符号链接或环境变量。

17 项审批流程、5 项扫描/Codex、7 项存储及 3 项 OpenCode 测试通过，58 项前端回归通过。策略语义升级为 tools8，旧绑定不匹配；新后台尚待重载，OpenCode 已运行实例需加载更新插件后才会上报实例目录。不自动修改或重启用户客户端。

随后 39 项隔离 HTTP/真实钩子进程协议回归通过（20.019 秒），无用户真实工具执行；这验证服务协议兼容，不等同于所有客户端版本都会上报 cwd。

后续真实 CLI 验证：Codex 0.128.0 四类补丁场景及 OpenCode 1.19.0 三类补丁场景均通过，事件目录摘要与独立临时项目路径匹配。Codex 同会话批准后完全相同动作只放行一次，产生真实临时文件与工具返回，再次调用重新要求复核。OpenCode 普通新增返回、敏感新增及删除停止且文件状态符合预期。报告 codex-context-verification.json、opencode-context-verification.json；模型为回环固定响应，审批只在测试内存引擎模拟，未处理用户真实事件。Codex 拒绝后仍没有执行后回执，测试仅通过拒绝返回消息与临时文件状态交叉核对，不将其历史 execution_state 改成 blocked。未验证运行中切换目录的真实客户端行为或所有工具类型。

来源定位的手动说明与请求失败按事件留在当前窗口内存，定时刷新不会立即抹去；切换事件不会串用上一条提示。缓存最多 200 项，不持久化。OpenCode 的后台定位回执仍优先展示。不新增自动重试、批准或命令执行。

授权消费和撤销的最终状态现在与授权操作在同一事务内写回原事件。临时授权行超过五分钟清理后，原事件仍保留“已使用”或“已撤销”，不会退回“已过期”。启动时对旧库尚存的 consumed/revoked 授权行补齐事件状态；旧版本已经删除的授权行无法无证据重建，不猜测修复。未收到执行回执的事件仍显示未知，授权历史不构成执行成功证明。

详情页在最近 200 条记录中按 `approved_from` 关联原审批与重试动作，提供双向查看按钮；按钮只切换 Guardian 详情，不重新调用工具、不重复审批。关联动作超出窗口时明确提示无法从当前列表判断执行结果，不猜选其他事件。

## 检查上下文变化后的旧请求

模式切换、本地语义配置变化及服务重启会将尚未过期的待审批请求和未使用授权一并标为 revoked，保存具体原因。不能只撤销已批准的授权，再允许用户从旧待审批卡片创建一份无法匹配当前检查的授权。规则版本不匹配的请求也不能被批准，列表显示规则变化提示。已消费、已拒绝和执行回执保持原记录；已经过期的请求继续显示过期。

语义配置先完成参数校验，再在同一配置操作内撤销旧请求；撤销提交失败时配置与语义版本不变。无效配置请求不会撤销授权。模式保存失败仍可能留下已安全撤销的请求，但不能留下变更模式后的旧可用授权。服务启动时撤销失败会停止启动，不宣称服务已经就绪。

界面分别说明规则、模式、语义配置或服务重启原因，要求在原客户端重新发起动作检查，不自动恢复执行。服务重启后的这项失效是预期行为；全局客户端接入配置不因此移除。
# 执行前语义实验的授权边界

Codex CLI 0.128.0 的真实补丁验证中，PreToolUse 拒绝原因已返回客户端模型上下文，文件保持未修改，但被拒绝的调用不发送 PostToolUse。此时 Guardian 保留判定与待审批状态，执行回执仍为 unknown；不能把发出拒绝决定伪装成客户端回执。正常写入收到 PostToolUse 后为 tool_returned，该状态本身也不等同于对任意工具副作用的独立验证。已放行动作仍可能被 Codex 自身沙箱拒绝。

执行前语义实验默认关闭。当前没有可信用户任务授权输入，因此进入该实验检查的动作即使返回“未发现额外线索”，保护模式仍需原生确认或精确一次性审批；观察模式只告警。事件明确说明是缺少任务授权，而非已证实危险。批准只绑定该客户端、会话、工具和完整参数，改变参数必须重新检查，不能自动重放。已有明确规则决定和只读跳过路径不因此改变。该限制防止模型过度自信被当成授权，但会增加确认次数；不能替代后续可信上下文和效果验证。


## 审批与停止回执分开统计（2026-11-03）

待审批计数以 pending 授权状态为准，不能因为原调用上报 blocked 就从待处置计数消失。已批准但未消费的授权单独显示“待原会话重试”，不当作待审批或已执行。已拒绝、过期或撤销的审批不再计为待审批；如果原调用一直没有执行/停止回执，仍进入回执待核对（支持回执的客户端），不推断失败。

Claude 原生确认仅在该调用尚无回执时提示用户前往权限提示；收到 tool_returned、blocked 或 failed 后显示实际回执及“没有独立原生审批决定回执”，不继续显示等待确认，也不伪造授权记录。12 项诊断测试及 60 项前端测试通过，覆盖停止后仍待审批、批准后等待精确重试、授权消费、拒绝后缺少回执及原生工具返回。源码尚未重载到日常后台，不作为已部署证据。


## Codex 原始工具与数组参数绑定（tools9）

检查发现旧适配器把 shell/exec_command 等工具统一改名为 Bash，并将 command 数组用空格拼接后覆盖原值，导致不同参数边界可能具有同一授权摘要。现在适配器保留原工具名、参数键、字符串/数组类型及元素边界，规则归一化仅操作独立副本。原始工具名、参数类型或数组边界变化均不能消费原单次授权；重复调用 ID 配上不同参数被拒绝。cmd 与 command 不再互相补写到原始参数中。

数组命令仍产生有限词法风险线索，但不声称已解析 argv/解释器语义；标为 generic_only，且不套用只打印或 WhatIf 的字面量豁免。没有执行测试中的上传或删除字符串。规则绑定版本升级 tools9，旧策略授权不能匹配新动作。

7 项发现/Codex、6 项覆盖、17 项审批及 4 项字面量规则测试通过。真实 Codex 0.128.0 隔离 CLI 的普通补丁、敏感新增阻止、删除阻止、一次授权重试四例再次通过，工作目录绑定全部成立；报告 .local/codex-tools9-verification.json。CLI 测试针对补丁回归，不是所有 Codex 版本 argv 工具的真实执行验证。日常后台仍为 tools8，这一修复尚待重载。

## 2026-11-11：陪伴观察与严格保护的体验边界

用户反馈后台未启动时 Claude 无法读写。只读排查确认用户级 Guardian PreToolUse Hook 存在，runtime-modes.json 中 claude-hook 为 protect，回环后台未响应；这是原严格保护的离线拒绝行为，并非已证明 Claude 自身 Hook 损坏。

本次按用户意图将当前安装的 claude-hook 模式设为 observe，修改前备份 runtime-modes.json，保留其他客户端模式和 Claude 配置。用实际安装路径、实际本地模式向 Hook 输入合成 Read 描述，后台不可用时输出观察缺口提示，没有 permissionDecision 拒绝；未执行文件读写，也不替代用户在真实 Claude 会话中的验证。

控制台将 observe 明确标为“陪伴观察 · 只提示，不阻断（推荐）”，protect 标为“严格保护 · 可阻断操作”。保存严格保护前需勾选确认后台离线也可能阻断读写；选择回观察不要求额外确认。Hook 未提供 mode 参数时默认 observe。严格保护的异常提示补充启动后台或切回观察的恢复方法，既有显式 protect 约束仍保留。

观察模式后台关闭后不由守卫阻断，但期间不产生有效监督判断或实时提示。全局 Hook 仍存在；关闭界面不等于撤销接入，亦未实现“关闭界面自动停止后台”的新行为。客户端本身的权限提示不会被守卫跳过。
