# 本机并发验证（2026-11-03）

使用 `scripts/benchmark_local.py` 启动独立回环服务、临时磁盘 SQLite 数据库；不读取真实 Agent 配置，不写正在运行的 Guardian 历史，不执行命令。合成动作按普通读取、递归删除文本、上传文本轮换，由测试端提交合成回执。后台另有每 200 ms 一次的控制台数据请求。

```powershell
python scripts/benchmark_local.py --actions 2400 --workers 8 --output .local/benchmark.json
```

输出包含失败记录、唯一事件数、保留数量、回执数量、数据库完整性及 HTTP P50/P95/P99。任何请求失败、事件身份重复或保留/回执数量不符合预期都会返回非零退出码。它不是实际 Agent 执行阻断测试。

Python 3.11.9、SQLite 3.45.1，Windows 主机；同一开发机上测试，其他应用和系统缓存未隔离，单次比较不能证明性能提升。

三次 SQLite 完整性检查均为 `ok`。原始报告在 `.local/benchmark-baseline.json`、`.local/benchmark-current.json`、`.local/benchmark-burst-baseline.json`。未把本轮 HTTP 结果宣传成性能提升：更新后 P95 略高，且有更高的长尾。

本轮实现了事件 ID 索引查找，以及按被淘汰记录定向移除授权，替代逐条 JSON 查找和每动作全历史授权清理。索引查询计划与关联授权保留已测试；这些路径优化不等于整体吞吐已经提升。依据 [SQLite 表达式索引文档](https://www.sqlite.org/expridx.html)，查询表达式与索引表达式保持一致。

保留原数据库持久化方式，未降低同步级别。事件 `latency_ms` 新增 scope，明确其只包含引擎锁等待与持久化前规则工作，不能替代 HTTP 延迟。报告的 service_construction_ms 仅测服务对象构建和线程启动，不是独立进程或模型冷启动；旧基线同一指标曾命名为 cold_service_ms，应按该限定理解。

`scripts/measure-desktop.ps1 -Seconds 60` 只读识别唯一运行中的 Guardian 桌面进程及其子进程，用进程创建时间避免 PID 复用误归属。记录 CPU、工作集之和、句柄及子进程变化，不存命令行、窗口标题或其他应用数据。CPU 为整机逻辑处理器归一化百分比；首个样本没有 CPU 差值，统计必须排除 null。

改动将每帧数百次径向渐变创建改为最多 8 张 128×128 透明渐变贴图，仍逐样本更新半径、投影和强度；保留软边光轨、端口球尾迹、真实事件抽取和脉冲。测试还发现火花寿命边界的浮点误差可能产生微小负透明度，现将强度限定到有效范围，避免 Canvas 忽略无效值后误用上一状态。

采样前后窗口生命周期、系统活动未隔离，未测 GPU、帧率或视觉等价性；这些数字是本机初步证据，不能证明长期资源门槛已通过。原生交互自检仅检验 DOM、命中区域和错误状态，不能替代用户对画面的验收。
