## 产品流程

1. 扫描本机：PATH、已知安装目录和必要的安装元数据；有超时、进度、取消与重新扫描。支持用户指定入口。不全盘递归扫描，不读密钥和会话历史。
2. 展示候选：名称、版本、路径、发现依据、可用接入方式和覆盖范围。安装位置发现与版本执行验证分开，未知可执行文件不自动运行。
3. 勾选接入：展示项目级或会话级配置范围和将产生的变更，默认观察模式。
4. 安装适配：统一调度现有 hook、plugin、MCP 等适配器，配置合并可重复执行，保留备份、支持撤销和冲突检测。
5. 无害验证：生成关联验证事件，分别记录适配器测试和真实客户端测试；根据真实回执更新状态。

## 内部模块建议

统一注册表记录 id、显示名、发现规则、版本能力、配置方式、验证方式和撤销方式。扫描层负责发现；适配层负责配置与接入；验证层负责证据；前端向导负责选择和呈现。现有 start-agent.ps1、prepare_agents.py 和各客户端适配器可逐步纳入该注册表。

状态至少区分：发现安装、支持适配、配置完成、收到检查事件、执行控制已验证、故障或失效。不能把“发现客户端”“MCP 演示成功”展示为原生所有工具已保护。Ollama 是模型服务来源，应与 Agent 客户端分组展示。

## 验收重点

- 已安装但不在 PATH、多个版本、路径含空格/中文、客户端未安装均可解释。
- 扫描失败与未找到可区分，某个客户端失败不阻塞其他候选。
- 配置幂等，不覆盖其他插件或用户配置；撤销仅清除本产品变更。
- 用户能从一个页面选中多个客户端，并看清各自覆盖和验证程度。
- 接入失效显示异常；历史事件不能被误读为持续在线。
