# 工具返回内容提示（2026-11-03）

对应原始验收 T10：工具返回可疑指令时标记其来源，后续工具调用继续独立检查。返回提示发生在工具执行后，不是执行前拒绝、自动撤销或审批授权。

## 当前链路

Claude PostToolUse / PostToolUseFailure 和 Codex PostToolUse 在本机 Python 钩子内扫描 tool_response；OpenCode tool.execute.after 扫描 output.output。只发送固定结构的版本、覆盖状态、扫描字符数、截断标记和 instruction_override 信号，不发送、保存或向复核模型提供原始返回正文。服务以客户端、会话与工具调用标识关联原事件，不修改原决定和执行回执。

悬浮窗能够提示较晚到达的返回风险；详情显示“返回内容待核对”及扫描范围。关闭提示不会授权动作。历史导出和可选摘要复核只携带上述扫描元数据。正常返回不会新增审批。

## 检测边界

这是词法信号，不是完整提示注入检测或因果判断。目前识别有限的忽略指令、system prompt 等表述；研究引用也可能命中，因此不凭这些返回文字禁止整个任务。未命中不代表内容安全，不理解混淆、编码、图片或附件；不判断后续动作是否由该文本诱发。

每次最多扫描 32768 个字符（JavaScript 按 UTF-16 单元）。Python 最多遍历 128 个结构节点，分别检查各字符串，不匹配跨字段拼接的短语；OpenCode 仅处理字符串。无内容、不支持的结构与截断分别记录。已有钩子输入总字节上限仍适用，超大钩子载荷可能无法上报回执，不能宣传任意长度覆盖。

## 验证范围

- Claude 真实 CLI 加本地伪模型：正常打印、隔离服务的合成拒绝、仅打印结果出现指令短语三例通过。
- OpenCode 真实 CLI 加本地伪模型：正常 echo、合成拒绝、echo 返回指令短语三例。OpenCode 的短语在参数中也存在，本例验证返回协议，不作为仅输出触发的证据；后到返回提示由独立界面测试覆盖。
- Python 钩子子进程传输测试验证 Claude/Codex 不上传正文；Codex 实际所有工具的 tool_response 结构尚未完整实测。Gemini 尚无返回扫描适配。
- OpenCode Windows Shell 不支持原验证脚本中的 printf 正常案例。脚本改用 echo，核对无工具错误、精确打印结果、单次新增事件；命令字符串出现在错误文本中不再算正常成功。生产规则未注入测试标记规则。

已运行的 OpenCode 进程需要重新加载插件才能采用新逻辑；不会自动关闭用户会话或改变模型配置。
