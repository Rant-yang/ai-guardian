# 新用户流程演练 · 2026-11-04

## 范围

从明确的源码发布清单展开新目录，不复制 `.local`、令牌、历史或原有虚拟环境。实际执行首次安装、重复安装、独立端口启动和重复启动。随后通过真实本地 HTTP 与实际 Python 钩子进程检查连接及动作链路；接入/撤销只作用于虚构用户目录。

这不是从 GitHub 下载的公开版本，也不是干净 Windows 虚拟机。主机已有 Python、WebView2、客户端安装及 pip 缓存；未向用户现有 Agent 对话发送消息。没有把模拟配置演练称为真实客户端全功能验收。

## 仍需优先完善

1. 安装依赖：Python/WebView2 仍是前置条件，应继续评估有签名的独立安装包与更清晰的缺失依赖修复入口。
2. 浏览器刷新：为了不持久化管理令牌，目前普通浏览器刷新后仍需重新双击启动器；原生窗口支持自动重新取票据。不能通过取消鉴权来省步骤。
3. 首次接入：扫描、选择、客户端信任/重启、真实动作验证应进一步形成清晰连续的向导；配置已写入与真实监督已生效必须分开。
4. 来源返回：多标签终端、IDE 终端和 Codex 可见会话仍未统一验证，这是核心功能缺口。
5. 安全效果：规则覆盖、误报漏报、单次审批后的重试与执行回执继续优先于新增视觉效果。
6. 发布验收：仍需无开发环境的新 Windows 和不同客户端版本验收；未发布到 GitHub。

## 令牌的产品原则

正常安装和双击启动不要求用户手工输入令牌。管理令牌保护本地审批与接入配置，上报令牌只给适配器使用。启动器自动换取短期、一次性连接票据；手填只作为排障后备。Ollama 本地模型与云端 API 配置不属于这项初始认证。


## 第二轮细查：异步操作与恢复

- 预览请求按最新选择生效，较慢的旧接入/撤销预览不能覆盖新预览。
- 重新扫描或开启录屏隐私使旧计划失效，隐私开启后迟到的扫描结果不再显示配置路径。
- 确认配置期间锁定重复提交、重新扫描及选项修改；前端过期计划提示重新预览，服务端仍独立校验期限和文件变化。
- 原生连接请求防重复；启动票据失效时自动尝试一次重新取票据，失败后提供手动重连，不无限重试。
- 认证失败提示优先引导本机重连或重新打开启动器，不再默认要求寻找管理令牌。

74 项前端回归通过，覆盖上述异步场景。仅修改前端交互，无规则、模型、客户端配置和视觉动效变更。普通浏览器刷新仍需通过启动器重新连接；原会话精准返回与新机器安装验收仍未完成。
