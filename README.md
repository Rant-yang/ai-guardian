## 为什么做 AI Guardian

你让 Agent 修改项目、运行命令、处理文件时，不一定会一直盯着每一次工具调用。多个客户端、多个对话同时工作时，更难及时留意哪个动作需要你确认。

AI Guardian 将**已接入客户端的工具动作汇聚到一个本地界面**。你可以继续和 Agent 对话，在需要注意时查看风险提示，而不必持续翻查多个终端的输出。

| 你希望获得的体验 | AI Guardian 如何提供帮助 |
| --- | --- |
| 工作时少一点打扰 | 默认观察模式记录和提示，不要求 Agent 因 Guardian 的风险判断停止动作 |
| 一眼感知 Agent 正在活动 | 透明悬浮球以轨道、粒子抽取和脉冲展示活动；常规通过动作不逐条弹窗 |
| 看懂为什么提醒 | 详情展示具体动作、目标、命中原因、可能影响与下一步建议，敏感信息脱敏 |
| 多个助手统一查看 | 汇聚支持的客户端事件，按客户端和会话筛选，区分检查、授权与执行回执 |
| 对高风险动作主动介入 | 在支持的客户端启用保护模式，发送拒绝或待确认决定；授权仅限绑定的单次动作 |
| 从提示追溯到上下文 | 打开对应事件详情，并在适配能力允许时请求定位原会话；不能定位时提供手动线索 |

### 平时陪伴，风险出现时再展开

**日常使用** → 悬浮球展示动态效果与动作活动。

**发现风险** → 弹出提示，说明发生了什么、为什么需要留意。

**人工介入** → 查看详情，按当前模式和客户端能力确认、拒绝或回到 Agent 处理。

**核对结果** → 查看收到的执行回执；授权不等于执行成功。

悬浮球的日常轨道动画属于装饰，动作抽取和风险提示由事件驱动。判断接入是否有效，请看真实事件与接入状态，不能只看球是否在动。

## 快速开始

**准备：** Windows、可用的 Python 3.11–3.13、Microsoft Edge WebView2 Runtime。首次安装需要网络下载桌面依赖。**基础规则监督不需要本地模型，也不需要模型 API 密钥。**

### 1. 获取项目并安装

从仓库页面选择 **Code → Download ZIP**，完整解压后双击 **`Install.cmd`**。也可以使用 Git：

```powershell
git clone https://github.com/Rant-yang/ai-guardian.git
cd ai-guardian
.\Install.cmd
```

私有仓库需要先获得访问权限。安装器使用项目内的独立 Python 环境，完成后自动打开控制台，**无需手动输入管理令牌**。缺少依赖时按提示补齐，再运行同一入口。

### 2. 选择你想监督的 Agent

在控制台打开 **管理接入与模式 → 扫描 → 勾选客户端 → 预览全局接入 → 确认**。

扫描只读；确认后才写入接入配置。已有配置修改前备份，保留其他插件、模型、API 和权限设置。首次试用建议只接入一款客户端，保持默认观察模式。

### 3. 验证一次真实动作

保存已有任务，按提示重新打开客户端，完成它要求的信任确认。点击 **检查接入是否生效**，让 Agent 读取一个普通项目文件，核对新事件及适配器支持的回执。

包内提供无害样例 `trial/sample.txt`；详细步骤见 [10 分钟试用指南](TRIAL.md)。**配置写入成功不等于运行中的客户端已经加载。**

### 4. 打开悬浮球，继续工作

从控制台打开桌面悬浮球，或双击 **`Guardian-Overlay.vbs`**。以后使用 **`Guardian.vbs`** 打开控制台，启动器会复用健康的后台服务。

## 支持哪些 Agent

扫描会检查已知客户端的安装与配置线索。下表六款已有接入实现；发现某个程序不代表它已受到监督，也不代表所有版本、工具和窗口均已覆盖。

| 客户端 | 接入方式 | 当前能力与限制 |
| --- | --- | --- |
| **Claude Code** | 用户级工具前后 Hooks | 支持检查、原生确认和拒绝；受客户端版本、信任及启用状态影响 |
| **OpenCode** | 用户级插件 | 多会话事件汇聚；待审批动作需授权后重新发起 |
| **Codex** | 原生 PreToolUse / PostToolUse Hooks | 需要支持 Hooks 的版本与客户端信任；本机已有监督可用反馈，其他版本仍需验证 |
| **Gemini CLI** | BeforeTool Hook | 已有真实 CLI 合成场景验证；暂不提供关联执行回执 |
| **Qoder CLI（实验）** | 工具前后 Hooks | 已处理本机启动 Shell 兼容问题；真实会话完整验收与自动返回原窗口尚未完成 |
| **Pi Coding Agent（实验）** | 原生扩展 | 已有隔离 CLI/RPC 执行验证；日常终端体验与来源窗口仍需验证 |

通过用户级 Hook 或插件接入后，支持的后续会话可共用本地服务，无需每次在专用终端输入启动包装命令。已经运行的客户端可能需要重启或重新加载；实际覆盖仍需验证。

## 观察与保护，由你选择

| 模式 | 行为 | 适合的使用方式 |
| --- | --- | --- |
| **陪伴观察（默认）** | 记录动作与风险提示，不主动阻断工具调用 | 先了解 Agent 行为，验证接入，日常低打扰使用 |
| **严格保护（主动启用）** | 在支持的执行前接口请求拒绝或确认 | 希望对风险动作进行执行前干预，并接受服务异常时可能阻止动作 |

确定禁止的行为可以直接拒绝；需要人工判断的行为进入确认流程。一次授权绑定客户端、会话、工具和参数，并设有效期；参数变化必须重新检查。支持原生确认的使用客户端确认，不支持暂停恢复的需要重新发起，Guardian 不自动重放动作。

观察模式下的风险提示不代表动作已经被拦截。详情会区分判定、授权和执行回执，未收到回执时不宣称成功。关闭弹窗不等于批准动作。详见 [保护与审批流程](docs/protection-workflow.md)。

## 本地优先，让数据边界清楚可见

- 默认使用本地规则，无遥测或隐式云端检测调用。后台仅监听本机回环地址。
- 控制台管理与适配器上报使用不同凭据，上报凭据不能审批或修改配置。
- 可选本地模型摘要复核需要显式操作，不改变规则或审批决定；执行前语义通道目前为默认关闭的实验功能。Ollama 在线不等于 Agent 已接入。
- 提供录屏隐私模式，隐藏目标、会话与配置线索；它不会遮挡其他应用或透明窗口背后的桌面。

详见 [隐私说明](docs/privacy.md)、[本地模型复核](docs/local-review.md) 和 [语义实验说明](docs/semantic-evaluation.md)。

## 遇到问题

| 你遇到的情况 | 从这里开始 |
| --- | --- |
| 安装中断、依赖不完整 | 重新运行 `Install.cmd`，复用或修复项目环境 |
| 桌面打不开、想检查接入 | 双击 `Check.cmd`，无需启动后台即可检查配置 |
| 想反馈试用问题 | 双击 `Feedback.cmd`，查看生成的诊断 JSON 后自行发送；不会自动上传 |
| 不再使用或准备移动目录 | 先运行 `Disconnect.cmd`，核对预览并输入 `REMOVE` 撤销本安装拥有的接入 |

诊断报告只包含程序摘要、系统类型、Python/依赖版本及客户端配置状态，不包含聊天、日志、令牌或配置正文。**不要上传整个 `.local`**，其中可能包含凭据和行为记录。

撤销后关闭 Guardian 窗口，运行 `scripts/stop-background.ps1` 正常停止后台，并重新打开 Agent 验证普通读写。遇到配置冲突时保留项目目录，按提示处理；不要先删除或移动文件夹。完整步骤见 [维护、更新与退出指南](docs/maintenance.md)。

## 当前边界与接下来的方向

当前规则是小规模启发式规则库，存在误报、漏报和工具覆盖缺口。没有告警不代表所有行为安全；未加载接入的工具不在监督范围内，同一系统用户下的恶意进程也不在强隔离保证范围内。

正在补齐的主要体验：

- **更省心的安装与升级：** 干净 Windows 首装验证、自动升级及目录迁移。
- **更准确地回到对话：** Codex/OpenCode 可请求打开或选择会话，Claude 可尝试前置关联终端；尚不能保证所有原窗口或标签页正确激活。[来源定位说明](docs/source-navigation.md)
- **更稳定的常驻体验：** 多屏、DPI、休眠恢复与长时间资源使用验证。
- **更可靠的判断：** 规则覆盖和独立效果评测、可选模型增强。云端复核尚未串入主判定流程。

自动化测试和本机演练不等于所有真实客户端或新机器均已通过验收。完整进展见 [目标核对](docs/goal-status.md) 与 [发布准备记录](docs/release-readiness.md)。许可证尚待确定。
